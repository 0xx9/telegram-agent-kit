# Growth playbook — how to get stars on this repo

This doc is for maintainers. The product quality comes first; distribution amplifies it.

## Week 1 — launch

1. **Polish README** — clear hero line, 30-second install, example prompts, screenshot/GIF optional
2. **GitHub topics** — add: `telegram`, `telegram-bot`, `cursor`, `cursor-skills`, `aiogram`, `telethon`, `agent-skills`, `developer-tools`
3. **Pin the repo** on your GitHub profile
4. **Post where Telegram devs hang out:**
   - r/TelegramBots
   - Telegram groups: @BotSupport, aiogram chat, Telethon chat
   - Dev.to / Hashnode article: "How I stopped AI from leaking my bot token"

## Week 2 — distribution

5. **Submit to awesome lists** (open PRs):
   - Search GitHub for `awesome-telegram`, `awesome-cursor`, `awesome-cursor-skills`
   - Add one line with a clear one-sentence value prop
6. **Short demo video** (60–90 sec) — Cursor building a bot with the kit installed
7. **Cross-link** from your other public bot repos' READMEs

## Ongoing — compound growth

8. **Ship one new skill per week** — each release is a reason to share again
9. **Respond to issues within 24h** — early repos win on responsiveness
10. **Accept community skills** — contributors become promoters
11. **Track star velocity** — [star-history.com](https://star-history.com), GitHub Insights

## What works in 2026 (from trending repos)

| Pattern | Example repos | Why it works |
|---------|---------------|--------------|
| One-line install | Understand-Anything, skills repos | Zero friction to try |
| Agent-native | Cursor/Claude/Codex skills | Rides the AI coding wave |
| Solves one painful moment | First deploy, first payment | Shareable "this saved me" posts |
| Multi-language README | EN + AR/RU/ZH | Wider discovery |

## What to avoid

- Buying stars or bot traffic (GitHub detects this)
- Overpromising ("100k stars guaranteed")
- Copy-pasting PatrickJS/awesome-cursorrules — differentiate or contribute upstream instead
- Shipping skills with fake benchmarks

## Metrics to watch

- Stars per week (goal: 50+ in first month for a niche kit)
- Clone count (GitHub traffic)
- Inbound PRs and issues
- Referrers in GitHub Insights (which posts drive traffic)
